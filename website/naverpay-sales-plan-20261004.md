# 네이버페이 판매 연동 준비 — 2026-10-04

상태: 요구사항·공식 지원 범위·현재 코드 확인. 실제 가맹·인증·결제 호출·판매 활성화는 미완료.

## 선택할 연동 경로

목표는 GroundRooted 자체 사이트에서 앱을 구매하고 네이버페이로 결제하는 것이다. 다운로드형 소프트웨어에는 비실물 상품을 지원하는 결제형이 적합하다. 주문형은 공식 비교표상 실물 상품만 지원하므로 이 프로젝트의 기본 경로로 선택하지 않는다. 개별 소프트웨어 상품의 실제 가맹 가능 여부는 취급 상품 심사로 확정한다.

- [네이버 공식 결제형/주문형 비교](https://developers.pay.naver.com/introduce/naverpay)
- [네이버 공식 가입·개발·검수 절차](https://developers.pay.naver.com/introduce/process)

| 경로 | 적용 조건 | 프로젝트 판단 |
| --- | --- | --- |
| 토스페이먼츠를 통한 네이버페이 | PG 계약, 네이버페이 사용 가능 계약 상태, 소프트웨어 상품 심사 확인 | 기존 설계의 Toss 국내 결제 경로와 일치하므로 우선 추천. 아직 사용자 확정·가맹 확인 전 |
| 네이버페이 결제형 직접 연동 | 사전 제휴 협의, 가입 심사, 인증 정보 발급, 개발·서비스 환경과 결제 취약성 검수 | 이미 직접 가맹한 경우 해당 계약을 우선 활용 |
| 스마트스토어 링크 | 별도 판매 채널. 해당 상품의 등록·판매 가능 여부 확인 필요 | 자체 사이트 결제 API 연동과 동일하지 않음. 계정 보유만으로 소프트웨어 판매 가능이라고 판단하지 않음 |

토스페이먼츠 공식 FAQ는 주문서형·결제창형에서 네이버페이 등 간편결제를 제공할 수 있다고 안내한다. 결제수단별 계약 상태와 사용 가능한 카드/포인트/머니 범위는 계약에 맞춰 확인해야 한다.

- [토스페이먼츠 FAQ](https://docs.tosspayments.com/resources/faq)
- [결제수단 정책](https://docs.tosspayments.com/guides/v2/get-started/payment-methods)
- [테스트 환경](https://docs.tosspayments.com/guides/v2/get-started/environment)

## 현재 코드에서 확인한 차이

현재 사이트는 제품 소개 preview이며, 서버 가격표·고객 계정·주문 저장소·구매 권한 발급은 구현되지 않았다. `app/api/webhooks/stripe`는 내부 매출 수집용으로, 앱 구매 결제 승인에 재사용하지 않는다. HQ 공유 비밀번호는 고객 로그인 수단이 아니다. 상품 상태와 구매 조건은 현재 미확정으로 표시돼 있다.

기존 `groundrooted-implementation-plan-v1.0.md`의 고객·운영 데이터 분리, 서버 견적, 멱등성, 대사·복구 규칙을 유지한다. 이번 사용자 요구로 국내 결제의 네이버페이 지원을 필수 수용 조건에 추가한다. PG 경유/직접 연동이 결정되기 전 특정 provider의 승인 API나 공개 구매 버튼을 활성화하지 않는다.

## 구현 순서와 완료 기준

1. 가맹 상태와 경로 확인: 네이버 직접 가맹 여부, PG 보유 여부, 다운로드형 앱 판매 승인 여부를 확인한다. 비밀키는 대화나 저장소에 넣지 않는다.
2. 상품 확정: 첫 판매 앱, 실제 가격·통화·과세 구분·일회성/구독 여부·라이선스·지원 OS·환불 조건을 확인하고 서버 상품 설정에 등록한다.
3. 주문서: 제품/가격/권리/동의 내용을 표시하고, 로그인한 고객과 서버 주문을 결합한다. 구매자는 네이버페이를 결제수단으로 선택한다.
4. 승인: 성공 URL만으로 결제 완료를 판정하지 않는다. 서버에서 저장 주문·사용자·상품·금액·통화·환경·결제 식별자를 확인하고 승인/조회한다. 중복 호출과 승인 불확실 상태를 구분한다.
5. 권한 발급: 승인 결과를 내구성 있게 저장한 후 라이선스/다운로드 권한을 발급한다. 승인됐지만 발급이 지연된 경우 재결제를 유도하지 않고 복구한다.
6. 취소·환불: 실제 PG 거래 상태와 내부 권한을 대사한다. 환불 후 권한 정책도 상품 계약에 맞춰 처리한다.
7. 검증: 정상 승인, 고객 취소, 승인 거절, 금액 변조, 다른 사용자의 주문, 중복 승인, 타임아웃·재시도, 발급 지연, 환불·재구매를 테스트한다. 샌드박스 검증과 실거래/배포 검증은 구분한다.

## 사용자 확인 대기

현재 네이버페이 가맹 신청 전 / 직접결제 가맹점 보유 / 스마트스토어 보유 여부를 질문했다. 이 상태에 따라 연동 경로가 달라진다. 첫 판매 상품과 가격, 고객 주문·라이선스 시스템 유무도 실제 연동 전 확인해야 한다. 현재 인증 정보 확인이나 실제 결제 요청은 수행하지 않았다.
