# ReadyMD 홈페이지 스토리텔링 계획서 1.0

작성: 2026-09-23 · 상태: 구현 전 콘텐츠 재기획안

대상: 현재 `/pdf-to-md`의 ReadyMD 제품 소개 페이지. 사이트 코드·앱 기능·배포는 이번 작업에서 변경하지 않는다. GroundRooted 전체 홈페이지와 다른 제품 페이지로의 확장은 이 서사를 검토한 뒤 별도로 정한다.

근거: [네이버·와디즈 조사 기록](readymd-storytelling-research-20260923.md), [사용자가 설명한 제품 특징](pdf-product-story-20260920.md), [현재 디자인 규칙](../DESIGN.md). 네이버 TOP 10의 상세 본문은 보안 확인으로 미확인이다. 이 문서는 확인한 목록·와디즈 상세 텍스트와 일부 이미지·제조사 공식 설명을 토대로 작성한 1차 계획이다.

## 1. 이번에 바꿀 핵심

**중심 콘셉트: 모아 둔 PDF를, 읽고 다시 쓰는 나의 지식으로.**

방문자가 먼저 이해해야 할 설명은 다음 한 문장이다.

> ReadyMD는 읽기 불편한 PDF를 편하게 읽고, AI와 함께 활용할 수 있는 파일로 바꾸는 앱입니다.

이 문장은 사용자가 설명한 제품 방향을 쉽게 풀어 쓴 기획 문구다. 모든 PDF·뷰어·AI 도구에서 같은 결과를 보장하는 뜻이 아니다. 실제 출시 문구는 대표 파일로 검증한 뒤 확정한다.

페이지를 읽는 동안 방문자의 생각이 이렇게 바뀌게 한다.

**“내가 겪는 일이다” → “이렇게 바뀌는구나” → “내 자료에도 써 보고 싶다” → “어떻게 쓰는지 알겠다.”**

현재 페이지는 두 결과 형식과 여러 기능을 반복해서 설명한다. 새 구성은 하나의 PDF가 사람의 하루에서 달라지는 과정을 따라간다. 기술 용어를 미리 알아야 이해할 수 있는 문장을 줄인다.

## 2. 누구의 이야기로 만들 것인가

핵심 고객은 **논문·보고서·책·강의 자료를 PDF로 모으고, 읽은 내용을 글이나 수업·발표에 다시 쓰는 사람**으로 가정한다. 실제 고객 인터뷰로 확인한 시장 분류는 아니다. 사용자의 우선 고객 답변이 오면 대표 장면의 순서만 조정한다.

| 우선순위 | 대상과 구체적인 순간 | 먼저 보여줄 이득 | 사용할 장면 |
| --- | --- | --- | --- |
| 1 | 연구자·대학원생·지식 근로자: 자료는 받았는데 작은 글씨 때문에 읽기가 자꾸 끊긴다 | 읽을 때 생기는 마찰을 줄인다 | 같은 보고서가 읽기 편한 화면으로 바뀌는 모습 |
| 2 | 목회자·교사·강사·기획자: 읽은 자료를 설교·수업·기획에 다시 참고하려 한다 | 글과 그림을 함께 정리해 다음 작업에 가져간다 | 본문과 연결된 도표를 확인하고 자료 파일을 준비하는 모습 |
| 3 | 개인 지식관리 사용자: PDF는 쌓이지만 자기 생각과 이어지지 않는다 | 보관한 자료를 다시 꺼내 쓸 수 있게 한다 | 읽기용 파일과 재사용할 파일을 구분해 보관하는 모습 |

직업 이름을 첫 화면에서 길게 나열하지 않는다. 누구나 알아볼 수 있는 PDF 사용 장면으로 시작하고, 중간에 자신의 경우를 찾도록 한다.

ReadyMD의 필요성이 낮을 수 있는 경우도 안내한다. 현재 PDF가 이미 잘 읽히고 사용 중인 AI 도구에서도 필요한 내용을 충분히 활용한다면, 굳이 변환할 이유는 작을 수 있다. 스캔 자료·작은 글씨·문서 재사용에서 구체적인 어려움이 있는 사람에게 집중한다.

## 3. 첫 화면: 브랜드 문구와 제품 설명을 함께

사용자가 정한 세 문구는 유지한다.

- 제품명: **ReadyMD 레디엠디**
- 메인 타이틀: **For Your 2nd Brain**
- 타이틀 바로 아래 부제목: **지성 확장의 시작**

그 아래 설명은 다음처럼 바꾼다.

> 모아 둔 PDF, 이제 편하게 읽고 다시 활용하세요.
> ReadyMD가 읽기 좋은 전자책과 AI에 활용할 자료 파일로 바꿔드립니다.

첫 화면의 역할은 제품의 정체를 알려주는 것이다. ‘2nd Brain’이나 ‘지성 확장’만 읽고 앱의 기능을 추측하게 두지 않는다. 핵심 설명이 모바일에서도 주요 버튼 앞에 보여야 한다.

버튼은 **“달라지는 모습 보기”** 하나를 주 행동으로 둔다. 클릭하면 같은 PDF의 전후 장면으로 이동한다. 보조 링크가 필요하면 “사용 방법”으로 둔다. 현재는 웹에서 변환하는 앱이 아니므로 “내 PDF 변환하기”, 실제 앱 출력이 없는 상태에서 “무료 체험”이라고 쓰지 않는다.

첫 화면 Lightfall은 기존 규칙을 유지한다. 사용자가 이전에 제거한 EPUB 조작 카드를 히어로에 다시 넣지 않는다. 첫 비교 시연은 히어로 아래의 이야기 안에서 시작한다.

## 4. 전체 이야기: 8개 장면

### 장면 1. 제품을 한 문장으로 이해한다

위 첫 화면 카피를 사용한다. 여기서는 OCR·EPUB·Markdown·리플로우를 나열하지 않는다.

독자의 질문: **“무슨 앱이지?”**

답: **“PDF를 읽고 활용하기 편하게 바꿔주는 앱이구나.”**

### 장면 2. 내 상황을 알아본다

**제목**

> 읽으려고 저장했는데,
> 다시 열어보기는 어려웠던 PDF.

**본문 초안**

> 휴대폰에서는 글씨가 작아 자꾸 확대하게 되고,
> 필요한 문장을 옮기려면 줄바꿈부터 다시 손보게 됩니다.
> 표와 그림은 따로 챙겨야 하기도 하죠.

**보여줄 것**

같은 보고서의 한 페이지를 세 가지 짧은 장면으로 보여준다. 작은 글씨를 확대하는 순간, 문장을 가져와 정리하는 순간, 본문 옆의 도표를 다시 찾는 순간이다. 해당 어려움이 실제로 있는 샘플을 고르고 모든 PDF에서 발생한다고 표현하지 않는다.

방문자를 게으르다고 탓하거나 “PDF는 AI가 못 읽는다”는 잘못된 전제로 시작하지 않는다. 많은 AI 도구가 PDF를 직접 처리할 수 있으므로 직접 처리와 차이가 생기는 문서·활용 상황을 보여줘야 한다.

### 장면 3. 같은 자료가 달라지는 것을 본다

**제목**

> PDF 하나에서,
> 읽기와 활용의 두 가지 길이 열립니다.

**짧은 설명**

> 내가 읽을 때는 편한 전자책으로.
> 다시 활용할 때는 글과 그림이 연결된 자료로.

**보여줄 것**

대표 PDF 한 개 → ‘편하게 읽기’와 ‘AI와 활용하기’의 두 결과. 새로운 예제를 계속 등장시키지 않는다. 원문의 제목·같은 문단·같은 도표가 결과에도 이어져야 한다.

이곳이 페이지의 첫 번째 증거다. 파일 아이콘 세 개만 보여주는 도식으로 끝내지 않는다. 결과를 한눈에 비교할 수 있는 화면을 먼저 두고, 설명은 짧게 붙인다.

실출력 확보 전에는 **“사용 방식을 보여주는 예시”**로 표시한다. 현재 SVG와 작성한 본문을 실제 변환 품질의 증거로 사용하지 않는다.

### 장면 4. 내가 읽는 시간이 편해진다

**제목**

> 글씨를 키워도,
> 문장은 화면 안에서 이어지도록.

**본문 초안**

> 작은 글씨에 눈을 맞추지 않아도 됩니다.
> 읽기 편한 크기로 바꾸고, 이어지는 문장을 따라가세요.

**체험**

현재 `ReadingExperience`의 글자 크기 조절을 중심 시연으로 사용한다. 방문자가 한 번 조작하면 같은 문장이 커지고 줄이 다시 배치된다. 버튼은 ‘작게 / 크게’처럼 의미가 바로 보이게 한다.

시연 바로 아래에서 처음으로 용어를 설명한다.

> EPUB은 글자 크기를 바꿔 읽을 수 있는 전자책 파일입니다.
> 읽기 설정은 사용하는 전자책 앱에 따라 달라집니다.

모든 PDF 레이아웃이 원본 그대로 유지된다는 주장을 하지 않는다. 독서 습관이 생기거나 집중력이 개선된다는 효과도 아직 약속하지 않는다.

### 장면 5. 읽은 자료가 다음 작업으로 이어진다

**제목**

> 읽고 끝내기 아까운 자료,
> 다음 글과 수업에도 이어 쓰세요.

**본문 초안**

> 본문의 제목과 문단을 정리하고,
> 관련된 표·사진·그림도 함께 챙깁니다.
> 이 자료를 읽을 수 있는 AI 도구에서 다음 작업에 활용하세요.

**보여줄 것**

같은 보고서의 도표가 어느 문단에 연결되는지 보여준다. ‘AI와 활용하기’를 선택하면 먼저 읽기 쉬운 본문과 도표 관계를 보여주고, 원문 Markdown 문법은 ‘파일 구조 보기’에서 펼친다. 코드 블록을 화면의 주인공으로 두지 않는다.

이제 결과 형식을 설명한다.

> Markdown은 제목·문단·표를 정리한 텍스트 파일입니다.
> 사진과 그림은 별도 폴더에 담고, 본문에서 연결합니다.

**가까이 붙일 조건**

> 이미지를 함께 활용하려면 AI 도구가 해당 이미지 파일을 읽을 수 있어야 합니다.

ReadyMD가 직접 답변을 만들거나 AI 서비스로 자동 전송하는 것처럼 연출하지 않는다. 특정 도구의 이름·로고·작동하는 대화 결과는 실제 호환을 확인한 뒤에만 사용한다. ‘발표 초안 완성’ 같은 결과는 외부 AI에서 사람이 별도 작업하는 단계임을 드러낸다.

### 장면 6. 내 용도에 대입한다

**제목**

> 이런 자료가 쌓여 있다면,
> ReadyMD가 필요한 순간입니다.

직업별 기능 목록 대신 세 장면을 짧게 제시한다.

| 작은 이야기 | 페이지에 쓸 문장 | 보여줄 자료 |
| --- | --- | --- |
| 공부·연구 | “읽어야 할 논문과 보고서가 많을 때.” | 같은 보고서를 편하게 읽고 관련 문단을 확인하는 장면 |
| 수업·설교·콘텐츠 준비 | “읽은 자료를 다음 수업과 글에 다시 참고하고 싶을 때.” | 출처가 있는 본문과 도표를 다음 작업의 자료로 준비하는 장면 |
| 개인 자료 정리 | “모아 둔 PDF를 다시 꺼내 쓰고 싶을 때.” | 읽기용 전자책과 활용용 자료 파일을 보관하는 장면 |

이 장면은 활용 제안이지 고객 후기나 실제 고객 사례가 아니다. 가상의 고객 사진·별점·수치로 실사용 증거처럼 꾸미지 않는다. 문헌 관리·인용 자동 생성·폴더 자동 정리 기능도 새로 있는 것처럼 추가하지 않는다.

### 장면 7. 시작 방법과 신뢰를 확인한다

**제목**

> PDF를 고르고,
> 변환한 파일을 열어보세요.

**세 단계**

1. 바꾸려는 PDF를 선택합니다.
2. ReadyMD가 내용을 읽고 파일을 만듭니다.
3. 결과를 확인하고, 읽거나 다음 작업에 활용합니다.

실제 앱의 선택·변환·결과 확인 화면을 사용한다. 실행 화면이 없으면 정적인 사용 개념도임을 표시한다. 처리 시간과 클릭 수는 측정 전까지 숫자로 강조하지 않는다. EPUB/Markdown 선택 옵션의 실제 UI도 추정해 만들지 않는다.

**기술 설명은 여기서 짧게**

> ReadyMD는 내 컴퓨터의 모델로 PDF의 글을 읽고 재구성합니다.

OCR이 필요하면 ‘이미지 속 글자를 읽는 기술’이라는 설명을 붙인다. 이 페이지에서 엔진·모델 구조까지 길게 설명하지 않는다.

자료 처리 범위, 모델 설치, 변환 한계는 확인된 내용만 안내한다. ‘로컬 모델 사용’에서 ‘네트워크 전혀 없음’이나 ‘완벽한 보안’으로 의미를 넓히지 않는다. 실제 개발자의 제작 동기가 확보되면 2–3문장과 실명/실제 작업 장면을 여기에 넣을 수 있다. 현재는 꾸며 쓰지 않는다.

### 장면 8. 남은 질문에 답하고 행동한다

FAQ를 사용자가 결정할 때 묻는 순서로 재편한다.

1. 어떤 PDF를 바꾸면 도움이 되나요?
2. 변환 후 어떤 파일을 받나요?
3. 표와 사진도 함께 볼 수 있나요?
4. 어떤 컴퓨터와 전자책·AI 도구에서 쓰나요?
5. 원문과 다르게 변환되는 경우도 있나요?
6. 언제 사용할 수 있고 비용은 얼마인가요?

결과 편차는 원문과 비교해야 하는 조건으로 안내한다. 미확정 가격·지원 OS·라이선스·환불 정책은 임의 작성하지 않는다. 상세 법률·기술 경고가 매 섹션을 차지하게 하지 말고, 주장과 직접 연결된 조건은 가까이, 나머지는 FAQ에 모은다.

**마지막 문구는 기존 요청 유지**

> 사람이 읽고,
> AI와 함께 활용하도록.

현재 단계의 행동은 **“달라지는 모습 다시 보기”**다. 출시 안내는 짧은 상태 문구로 두고, 연결된 신청 기능이 생기기 전에는 이메일 신청 버튼을 만들지 않는다. 실제 배포·설치·가격이 준비된 이후에만 다운로드·구매 행동으로 변경한다.

별빛은 이 문구의 뒤 배경으로 유지한다. 푸터 별빛 정지 버튼을 다시 추가하지 않는다. 기존 모션 감소·화면 밖 렌더링 중단은 유지한다.

## 7. 시각 자료와 제작 원칙

- 대표 원본은 권한을 확보한 한 개의 짧은 보고서로 통일한다. 문단·표·사진 또는 그래프가 함께 있는 자료가 좋다.
- ‘읽기 전후’에서는 같은 문장을, ‘AI 활용’에서는 같은 도표를 재사용한다. 내용이 바뀐 것과 표현 방식이 바뀐 것을 혼동시키지 않는다.
- 한 화면에는 핵심 문장 하나, 보여주는 변화 하나를 둔다. 대형 이미지 안에 모든 글자를 굽는 긴 상세페이지 방식은 가져오지 않는다. 본문은 선택·확대·검색 가능한 웹 텍스트로 구현한다.
- 자동 재생 긴 영상보다 정지 화면과 짧은 조작 시연을 우선한다. 필수 설명을 탭·스크롤 애니메이션 안에 숨기지 않는다.
- 모바일에서 ‘문제 장면 → 같은 자료의 결과’가 가까이 이어져야 한다. 실제 픽셀 높이는 와이어프레임에서 검수한다.
- 밝은 바탕, 청색 강조, 그림자·hover·장식 외곽선 금지, 접근성 포커스를 유지한다. 경쟁 상세페이지의 장식·과장 표현까지 복제하지 않는다.

## 8. 다음 제작 순서와 완료 기준

1. **서사 검토:** 주 대상, 대표 자료, 위 카피의 쉬운 설명을 먼저 확정한다. 지금 단계의 산출물은 이 문서다.
2. **증거 준비:** 같은 원본의 실제 EPUB·Markdown·이미지와 앱 실행 화면을 확보한다. 결과 편차와 제한도 기록한다.
3. **와이어프레임:** 모바일에서 제목만 읽어도 ‘문제→변화→활용→방법’이 이어지는지 확인한다. 이 단계에서 불필요한 섹션을 더 줄인다.
4. **페이지 구현:** 기존 컴포넌트를 재구성하고 중복 설명을 합친다. 계정·결제·메일 신청·실시간 변환은 별도 기능 범위다.
5. **이해도·실행 검수:** 실제 대상 사용자와 브라우저에서 각각 확인한다. 승인되지 않은 배포는 수행하지 않는다.

## 9. 우선순위

**필수:** 쉬운 첫 설명, 대상의 불편, 같은 PDF의 전후 증거, 읽기와 활용의 차이, 실제 사용 조건.

**증거 확보 후:** 실제 사용자 사례, 제작자의 진짜 동기, 특정 AI 도구 활용 시연, 정량 비교.

**이번 재기획에서 제외:** 신규 변환 기능, 회원가입·결제 구현, 디자인 효과 추가, 할인·카운트다운, 근거 없는 후기와 성과, 모든 직업을 포괄하는 기능 목록.

이 문서의 내용 구성은 기존 계획의 기능 중심 S01–S10을 재검토하기 위한 대안이다. 실제 구현 착수 전까지 현재 사이트와 기존 인증·거래·운영 설계를 변경하지 않는다.
