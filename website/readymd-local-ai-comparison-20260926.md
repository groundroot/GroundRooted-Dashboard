# ReadyMD 로컬 AI 이유·비용·파일 한도 비교

공식 자료 확인: 2026-09-26. `/pdf-to-md#why-local`에 구현. 로컬 미리보기: <http://127.0.0.1:3029/pdf-to-md#why-local>.

## 이번 요청과 구현 범위

사용자가 요청한 ‘민감한 문서를 외부 업로드하기 어려운 이유, GPT API 문서 인식 비용, NotebookLM 기준 파일 용량·개수 제한’을 하나의 시각적 비교 섹션으로 구성했다.

- 자료 이동: 내 PDF → 로컬 AI → EPUB/MD/이미지와, 자료 → 외부 서비스의 처리 경로를 비교한다.
- 비용: 문서 수·페이지·전체 재처리 횟수를 변경하면 두 GPT 모델의 API 예상 비용과 로컬 처리 구간의 외부 API 호출료를 표시한다. 토큰 가정과 계산용 환율도 변경할 수 있다.
- 한도: 200MB·50만 단어의 큰 숫자, 요금제별 소스 수 막대, PDF 50/100/500개에 필요한 노트북 수, ReadyMD/NotebookLM/GPT API 비교표를 제공한다.
- 공식 출처와 확인 날짜, 계산 공식·제외 비용, 계정별 자료 처리 조건을 페이지에서 열어 볼 수 있다.

React 클라이언트 상태와 확정적 산식으로 계산한다. 외부 AI 호출, 문서 업로드, API 인증, 비용 결제는 발생시키지 않는다. 새로운 의미 판단/LLM 통합이 없어 TypeSafe API를 추가하지 않았다.

## 공식 근거와 해석

### GPT API 비용

- [GPT-4.1 공식 모델 문서](https://developers.openai.com/api/docs/models/gpt-4.1): 100만 토큰당 비캐시 입력 $2, 출력 $8.
- [GPT-5.4 mini 공식 모델 문서](https://developers.openai.com/api/docs/models/gpt-5.4-mini): 100만 토큰당 비캐시 입력 $0.75, 출력 $4.50.
- [OpenAI 파일 입력](https://developers.openai.com/api/docs/guides/file-inputs): PDF는 추출된 텍스트와 페이지 이미지를 처리한다. PDF 이미지 detail 설정·내용에 따라 토큰 사용이 달라진다.

비교용 모델 두 종이다. 최신 모델 전체 목록, 모델 추천, 동일 OCR 품질 비교라고 표시하지 않는다. 공식 모델 페이지의 일반 토큰 단가를 사용하며 Batch·캐시 할인을 적용하지 않았다.

**기본 시나리오**

문서 20개 × 50쪽 × 전체 재처리 1회 = 1,000쪽.
페이지당 입력 텍스트 1,000 + 이미지 입력 1,000 = 2,000토큰, 출력 1,000토큰.
총 입력 200만, 총 출력 100만 토큰.

| 모델 | 입력 | 출력 | 합계 | 환율 1,400원 가정 |
| --- | ---: | ---: | ---: | ---: |
| GPT-4.1 | $4 | $8 | $12 | 16,800원 |
| GPT-5.4 mini | $1.50 | $4.50 | $6 | 8,400원 |

이미지 1,000토큰/쪽은 측정값·고정 요금이 아닌 조정 가능한 예시다. 입력 토큰에 글과 이미지를 모두 포함하고, 전사한 내용을 되돌려 받는 출력 비용도 계산한다. 문서를 페이지별 요청으로 나누는 가정이며 전체 문서를 한 요청에 넣는다고 가정하지 않는다. 환율은 실시간 조회값이 아니다.

산식: 문서 수 × 페이지 수 × 전체 재처리 횟수 × [(텍스트 입력 + 이미지 입력) × 입력 단가 + 출력 × 출력 단가] ÷ 1,000,000.

GPT-5.4 mini는 추론 none을 가정한다. 시스템 프롬프트, 추가 추론, 재시도, 도구·저장 요금, 지역 할증·세금은 제외한다. 읽기나 질문 한 번마다 전체를 재과금한다고 주장하지 않는다. 캐시·검색·부분 전송에 따라 반복 비용은 달라진다. ChatGPT 구독·NotebookLM 구독 요금과 API 과금을 혼동하지 않는다.

로컬 $0는 외부 AI API를 호출하지 않는 OCR 구간의 호출료만 뜻한다. 앱 가격(미정), 전기·장비 비용을 포함한 총비용이나 무료 앱을 뜻하지 않는다.

### NotebookLM 파일과 소스 한도

조사 당시 기존 notebooklm 도움말 주소가 gemininotebook으로 이동했고 공식 제목은 Gemini Notebook이었다. 사이트에는 사용자가 아는 NotebookLM과 현재 공식 명칭을 함께 표기했다.

- [파일·소스 제한](https://support.google.com/gemininotebook/answer/16215270?hl=en): 소스당 최대 50만 단어, 업로드 파일당 최대 200MB.
- [요금제별 공식 한도](https://support.google.com/gemininotebook/answer/16213268?hl=en): Standard 50, Plus 100, Pro 300, Ultra 20TB 500, Ultra 30TB 600 소스/노트북.
- PDF 한 개를 소스 하나로 등록하고 각 파일이 다른 한도를 충족한다는 가정으로 필요한 노트북 수를 `ceil(PDF 수 / 소스 한도)`로 표시한다. PDF 500개면 10/5/2/1/1개다.
- 위 수는 노트북에 등록할 수 있는 소스 수다. 동시에 업로드하는 파일 개수, 모든 문서를 한 답변에서 완독하는 양, 여러 노트북을 통합 분석할 수 있다는 보장으로 표현하지 않는다. 확인한 공식 문서에 공통된 ‘1회 업로드 최대 파일 개수’가 없어 숫자를 만들지 않았다.
- [현재 사용량 제한](https://support.google.com/gemininotebook/answer/17670842?hl=en): 2026-09-02부터 연산량 기반 한도, 5시간 갱신·주간 한도를 안내한다. 기존 업그레이드 표에는 과거 일일 채팅 수가 함께 남아 있어, 더 구체적인 변경 공지를 기준으로 고정된 하루 질문 횟수 비교를 하지 않았다.

### GPT API 파일 제한

[파일 입력 문서](https://developers.openai.com/api/docs/guides/file-inputs)는 직접 입력할 파일 각각 50MB 미만, 한 요청의 모든 파일 합계 최대 50MB를 안내한다. 여러 파일을 입력할 수 있지만 모델 문맥·요청 용량 안에서 처리해야 한다. ChatGPT 앱·Files API 저장 한도와 구분한다.

### 자료 보안과 제품 설명의 경계

- [OpenAI 데이터 정책](https://developers.openai.com/api/docs/guides/your-data): API는 기본 학습 제외. 악용 모니터링 등 보관 조건과 승인 기반 제어가 있다. ‘학습 제외’가 ‘외부 미전송’은 아니다.
- [Google 개인정보·피드백 정책](https://support.google.com/gemininotebook/answer/17004255?hl=en): 기본 학습 제외, 일반 계정 피드백의 관련 내용 검토·사용 조건. 적격 Workspace/Education 조건은 별도로 구분한다.
- ReadyMD의 로컬 처리는 사용자가 제시한 제품 설계 기준이다. 출시판 전체 통신·파일 처리 한도·실제 OCR 품질을 이번 웹사이트 작업에서 실측한 것이 아니다.
- 모델 다운로드·업데이트, 사용자가 결과를 외부 AI에 전달하는 단계는 로컬 OCR과 구분한다. 민감 자료에 관한 기관 규정 준수나 기기 보안을 자동 보증하지 않는다.
- ReadyMD 자체 파일·일괄 처리 한도는 미확정으로 표시한다. ‘무제한’은 쓰지 않는다. ReadyMD 결과를 외부 서비스에 올리면 그 서비스의 한도가 적용된다.

## 검증

- Node 24 프로덕션 빌드 및 Next TypeScript 검사 통과.
- `scripts/test-readymd-comparison.mjs` 통과: 기본 $12/$6, 반복 횟수, 이미지·출력 토큰 제외, 전부 0, 최소/최대 입력, 빈 값·음수·소수·범위 초과·비정상 값, 노트북 수 경계. Node가 모듈 형식을 재판별하는 경고는 있으나 테스트는 통과했다. 프로젝트 전체 모듈 설정은 변경하지 않았다.
- Ego Chromium 실제 브라우저: 기본 비용 표시, 5회 재처리 $60/$30, 이미지 0·환율 1,500원 변경 $10/15,000원, 0 토큰 막대 0%, 초기화, 빈 값 오류와 이전 금액 제거 확인.
- 계산에 사용 중인 토큰·환율이 화면 설명에도 갱신되는 것 확인. 환율을 실제 시세로 표시하지 않는다.
- PDF 500개 선택 시 Standard/Plus/Pro/Ultra의 필요한 노트북 수 10/5/2/1/1 확인.
- 320/390/768/1440px 가로 넘침 없음. 320px에서 허용 최대 입력(2천만 쪽 처리, 큰 원화 금액)도 페이지 가로 넘침 없음.
- axe-core 4.13의 WCAG 2 A/AA·2.1 AA·2.2 AA 태그 자동 검사 위반 0건. 계산 근거·고급 설정을 펼친 상태도 확인했다.
- 수집한 브라우저 오류/console.error 0건. 공식 출처 링크를 각 관련 영역에 배치했다.
- 데스크톱 데이터 경로·계산기·소스 한도, 모바일 계산기·소스 차트 스크린샷 확인. 모바일에서 수량 단위가 줄바꿈되는 부분을 수정했다.
- 기존 서버는 유지하고 이번 검수용 3029 서버만 시작·갱신했다. 서버 실행은 `MARKETING_PREVIEW_ENABLED=true`, 비공개 HQ 인증 로직은 변경하지 않았다.
- `git diff --check` 통과. 기존 작업 트리의 변경·미추적 파일을 보존했다.

임시 스크린샷은 `/tmp/readymd-local-*.png`다. 실제 GPT API 과금·문서 전송, NotebookLM 계정의 실파일 업로드, 실제 앱의 통신 차단·OCR 출력·성능은 시험하지 않았다. Safari·실기기·수동 스크린리더·배포 검증도 하지 않았다. 이번 결과는 로컬 웹사이트 구현 및 Chromium 검수이며 배포·커밋·푸시는 실행하지 않았다.
