# 200쪽 스캔 책: $20 구독과 Astra API 비용

확인일: 2026-09-26. 공식 규칙을 적용한 계산이다. 실제 API 청구·OCR 실행 데이터가 아니다.

## 결론과 홈페이지 표현

- ChatGPT Plus 월 $20를 API 토큰 잔액으로 환산할 수 없다. API는 별도 과금이다. 구독의 고정 월간 PDF 완전 변환 권수도 공개 근거로 산출할 수 없다.
- Astra API 예산 $20, 200쪽, 쪽당 본문 출력 1,000토큰, 20쪽 독립 요청을 가정하면 high 이미지 기본 비용은 $15.968, 300dpi original은 $30.612다. 추론 등 추가 비용을 제외한 완성 권수 상한은 각각 1권·0권이다. Plus 처리량이 아니다.
- ‘200쪽을 처리한다’가 ‘200쪽 전체를 한 요청에 넣고 전체 본문을 한 답변으로 받는다’는 뜻일 필요는 없다. 배치로 나누고 결과를 합칠 수 있다.
- 더 좋은 모델이 항상 토큰 낭비라는 결론은 성립하지 않는다. 표·수식·다단 편집·어려운 문서는 고성능 모델의 품질 이점이 있을 수 있다. **반복적인 원문 인식에 드는 입력·출력 비용을 줄이고, 필요한 해석에 AI를 쓰자**가 근거에 맞는 메시지다.
- ReadyMD의 실제 정확도·속도·로컬 전체 데이터 흐름은 이번 조사로 검증되지 않는다.

권장 문구: ‘200쪽을 한 번 내 자료로. 다음에는 필요한 문단만 AI에게.’ 이미지가 필요한 분석에는 해당 이미지를 함께 전달해야 한다.

## 구독과 파일 업로드

[Plus 공식 안내](https://help.openai.com/en/articles/6950777-what-is-chatgpt-plus)는 월 $20와 API 별도 결제, 변동 가능한 사용 한도를 설명한다. Astra의 계정별 사용 가능 여부도 구독 가격만으로 가정하지 않는다.

[파일 FAQ](https://help.openai.com/en/articles/8555545-file-uploads-faq): 파일당 512MB, 문서당 200만 토큰, 이미지당 20MB, 최대 80파일/3시간(혼잡 시 축소 가능). 이 숫자는 성공적인 전 페이지 OCR 보장량이 아니다. 200쪽을 한 PDF로 첨부하면 파일은 하나지만, 200장의 이미지로 별도 업로드하면 파일 수가 달라진다. Plus 프로젝트당 25파일 역시 월간 처리 권수가 아니다.

같은 FAQ는 PDF Visual Retrieval을 Enterprise에 한정하고 나머지는 디지털 텍스트 검색으로 설명한다. 따라서 이미지뿐인 PDF를 Plus에 그대로 첨부하는 경로를 전 페이지 OCR과 동일시할 수 없다. 이미지 직접 입력·코드 도구·별도 OCR 경로는 구분한다. [Visual Retrieval](https://help.openai.com/en/articles/10416312-visual-retrieval-with-pdfs-faq).

## 계산 조건

- PDF의 각 페이지를 A4 300dpi 상당 2,480 × 3,508px 이미지로 명시적으로 래스터화해 입력한다고 가정. 스캔 PDF에 텍스트 레이어는 없음.
- 책당 200쪽. 20쪽씩 10회 독립 요청. 이전 페이지·결과·추론을 다음 요청에 누적하지 않는다.
- 지시문 요청당 200토큰. 본문은 페이지당 500/1,000/2,000토큰 시나리오. 한국어 글자 수와 토큰 수를 같다고 가정하지 않는다.
- `gpt-6-astra`, Standard, `prompt_cache_options.mode: explicit`이고 breakpoint를 두지 않아 캐시 기록·적중 없음. 일반 기본 캐시 동작을 그대로 쓴 청구액이 아니다.
- 추론 토큰은 실제 측정 전 알 수 없어 0으로 **계산에서 제외**한다. Astra가 추론 없이 실행된다는 뜻이 아니다. Astra는 reasoning none 미지원.
- 추가 내부 지시문·도구·저장·세금·환율·재시도·지역 요금·실패 요청·시간 비용은 제외.

## 이미지 토큰 재현

[공식 vision 규칙](https://developers.openai.com/api/docs/guides/images-vision): 32×32패치, Astra 배율 1.2. high는 2,500패치까지 축소. original은 원본 크기 유지(모델 차원 제한 적용), 30,000패치 초과 시 거절. 이미지 직접 입력의 auto는 original 방식이다.

원본: ceil(2480/32) × ceil(3508/32) = 78 × 110 = 8,580패치. ceil(8580×1.2) = **10,296토큰/쪽**, 200쪽 **2,059,200토큰**.

high: 공식 축소 알고리즘 → 1,334 × 1,888px → 42 × 59 = 2,478패치 → ceil(2478×1.2) = **2,974토큰/쪽**, 200쪽 **594,800토큰**. 최종 청구 반올림에 1토큰 차이 가능.

공식 예제 1024²→1229, 2048² high→3000, 4096×512 high→2458도 로컬 계산기로 검증했다.

주의: 이 값은 명시된 페이지 이미지의 계산이다. [직접 PDF 입력](https://developers.openai.com/api/docs/guides/file-inputs)의 내부 래스터 크기 실측치가 아니다. PDF 입력은 추출 텍스트+페이지 이미지를 보내며 Astra의 PDF auto는 high로 처리된다. 이미지 직접 입력의 auto와 혼동하지 않는다. PDF 입력 파일당 50MB 미만·합계50MB, 이미지 입력은 총payload512MB·최대1500장이고 토큰 한도도 별도로 충족해야 한다.

## $20 API 예산 계산

[모델 사양](https://developers.openai.com/api/docs/models/gpt-6-astra), [가격](https://developers.openai.com/api/docs/pricing): 짧은 문맥 입력 $10 / 출력 $50 (100만 토큰당). 요청 입력이 272,000을 넘으면 **전체 요청** 입력 $20 / 출력 $75. 20쪽 독립 요청은 원본도 206,120 입력토큰이므로 짧은 요율 적용.

기본 비용 = (쪽당 이미지토큰×200 + 지시문200×10)×10/1,000,000 + (쪽당 본문토큰×200)×50/1,000,000.

| 쪽당 본문 출력 가정 | high 이미지 | $20의 완성 권수 상한 | 300dpi original | $20의 완성 권수 상한 |
|---|---:|---:|---:|---:|
| 500토큰 | $10.968 | 1권 | $25.612 | 0권 |
| 1,000토큰 | $15.968 | 1권 | $30.612 | 0권 |
| 2,000토큰 | $25.968 | 0권 | $40.612 | 0권 |

0권은 한 권의 완전 변환에 $20가 부족하다는 뜻이며 부분 처리 불가를 뜻하지 않는다. floor(예산/비용)로 계산하고, 표시용 소수점 반올림은 계산 후 수행한다.

[계산 데이터 CSV](../public/media/readymd/astra-200-page-estimates.csv), [계산 모듈](../products/book-scan.ts), [회귀검증](../scripts/test-book-scan.mjs).

Batch/Flex 단가는 Standard의 50%다. 위 1,000토큰 시나리오를 같은 조건의 Batch/Flex로 처리하면 기본 비용 $7.984/$15.306, 예산상 상한 2권/1권이다. 처리 조건과 추론·기타 비용은 별도다. Standard 비용만으로 모든 API 경로가 비싸다고 단정하지 않는다.

## 한 번에 처리하기 어려운 정확한 이유

Astra 공식 최대 문맥 1,050,000 / 최대 입력 922,000 / 최대 출력 128,000토큰. 모델 페이지 MCP 원문에서 입력 상한도 확인했다.

- high 입력 594,800은 입력 한도 내. 하지만 쪽당1,000토큰 본문은 총200,000출력으로 출력128,000 초과. 문맥이 커도 출력 한도가 따로 있다.
- original 입력2,059,200은 입력 한도 자체 초과. 200이미지라는 개수보다 토큰이 먼저 문제가 된다.
- 쪽당500이면 출력100,000이라 high는 숫자상 들어갈 수 있다. 이를 ‘모든 200쪽 책은 불가능’이라 표현하면 안 된다. 추론·용량·정확도·계정속도한도는 별도다.
- 20쪽씩 처리하면 이미지 입력 high59,480/original205,920, 본문 출력20,000(쪽당1000)이라 각각 한도 내. 스캔 작업의 지속 처리는 가능하며 결과 검증·병합이 필요하다.
- [추론 가이드](https://developers.openai.com/api/docs/guides/reasoning): 추론도 출력 과금·문맥/출력 한도를 사용한다. 요청당 추론1,000이 발생하면 10회에 $0.50 추가,10,000이면$5 추가. 한도 도달 시 incomplete가 될 수 있으므로 완료 상태·누락 페이지를 검사해야 한다.

## 반복·캐시에 대한 공정한 비교

20쪽씩 독립 입력하면 20×10=200쪽, 누적 입력하면 20+40+…+200=1,100쪽이다. 이미지의 논리적 입력 합계는 5.5배다. high는 594,800→3,271,400토큰이다. original은 2,059,200→11,325,600토큰이지만 **원본 누적 방식의 후반 요청은 한도를 넘으므로 성공하는 처리법이 아니다**. 문맥을 유지하기 위해 전체 페이지를 다시 넣어야 하는 것은 아니다.

[캐시 공식 안내](https://developers.openai.com/api/docs/guides/prompt-caching): 기본 자동 캐시, 동일prefix 적중 시 입력 비용 절감. 짧은 문맥 cache write $12.50 / read $1. 캐시기록은 입력 요율을 대체하며 별도로 $10에 더하는 요금이 아니다. 최초기록1.25+후속9회적중0.9=2.15배의 기본입력비용으로,10회uncached10배보다낮다. 기록만하고재사용하지않으면비싸다. 캐시 TTL·prefix·라우팅에 따라 적중이 달라진다. 캐시가 문맥 길이를 늘리거나 출력본문 생성을 무료로 만들지는 않는다.

OCR만 다시 시키는 상황과 변환된 텍스트에 질문하는 상황은 다른 작업이다. 후자는 부분검색·본문재사용으로 입력을 줄일 수 있다. ReadyMD후 클라우드AI에 원문을 보내면 외부전송·그 서비스요금/한도는 여전히 적용된다.

## 실측으로 입증할 다음 데이터 — 아직 미수행

1. 사용 권한이 있고 외부 전송이 가능한 200쪽 원본과 페이지별 정답 본문을 고정한다. SHA256, 언어, 픽셀 크기, 텍스트 레이어 유무를 기록한다. 현재 대화에는 비교할 실제 PDF와 정답 본문이 제공되지 않았다.
2. 로컬 OCR, Astra high, Astra original을 같은 20쪽 묶음과 같은 출력 형식으로 비교한다. Astra는 low 추론부터 측정하고 스냅샷·서비스 티어·캐시 조건을 고정한다. 실패와 재시도도 포함한다.
3. 요청마다 입력·출력·캐시 읽기·캐시 기록·추론 토큰, 완료 상태, 시간을 저장한다. 본문·키·개인정보는 로그에서 제외한다. 실제 청구 요율에 대응하는 usage 필드명은 실행 전에 확인한다.
4. 문자 오류율 CER=(치환+삭제+삽입)/정답 문자 수, 누락·중복 페이지, 읽기 순서, 표 셀 정확도, 사람이 수정한 시간을 기록한다. 공백·줄바꿈 정규화 규칙을 공개한다. 전체 평균과 함께 스캔 불량·작은 글씨·표·수식별로 분리한다.
5. 단순 OCR과 추론이 필요한 페이지를 함께 평가한다. 요구 정확도에 미달한 결과를 저렴한 성공 사례로 세지 않는다. 동일한 캐시 조건에서 반복 측정해 완성된 한 권당 비용·시간·교정 시간을 산출한다.
6. 로컬은 하드웨어·전력·앱 가격·처리 시간을 함께 기록한다. 외부 API 0원을 총비용 0원으로 표현하지 않는다.

따라서 현재 확보한 것은 비용·한도의 구조적 근거와 재현 가능한 추정치다. ‘Astra보다 같은 품질로 몇 배 저렴하다’는 실증 주장은 이 벤치마크 완료 전 사용하지 않는다.

## 구현과 검증

- 홈페이지 #book-budget에 구독 구분, 해상도·본문량·예산 선택, 입출력 비용 막대, 각각의 한도, 누적 입력 5.5배 예시와 공식 출처를 추가했다. 기존 모델 계산기는 접기 영역에 보존했다.
- 범위는 공개 제품 페이지의 결정적 계산·UI·문서다. 실제 모델 호출, 새 API, DB, 인증, 결제, 라이선스, 배포 변경은 없다.
- Node 24 산식 테스트: 공식 예제 3개, 해상도, 패치 거절, 장문 요율 경계, 입출력 한계, 예산 경계 통과. 기존 비교 산식 테스트와 Next 생산 빌드·TypeScript도 통과했다.
- Chromium 조작: 원본 전환 $30.61, 예산 $100→3권, 빈 예산 오류 확인. 본문 500토큰→$10.97·토큰 한도 내, 2,000토큰→$25.97·출력 초과 확인. 320/390/768/1440px에서 가로 넘침 없음. 기본 화면과 상세 설명을 펼친 화면 모두 axe WCAG 2/2.1/2.2 자동 검사 위반 0. 데스크톱·모바일 스크린샷을 시각 확인했다.
- 유료 API 실행, 실제 OCR 정확도·속도, 실기기·Safari, 배포는 미수행이다.

- CSV는 기존 HQ 인증을 우회하도록 경로를 열지 않고, 계산 모듈에서 생성한 data URL로 내려받는다. 실제 브라우저 다운로드 파일의 7행(헤더+6개 시나리오)과 기본값 $15.968을 확인했고 정적 CSV와 동일성 테스트를 통과했다. 최종 생산 빌드 통과, 로컬 미리보기는 http://127.0.0.1:3030/pdf-to-md#book-budget.


## 후속: 결과 가독성 개선

- 사용자 요청에 따라 비용 $15.97 / $30.61과 $20 예산의 최대 1권 / 한 권에 부족을 나란히 배치했다. 예산 변경 시 두 결과가 함께 갱신된다. 본문량·예산 설정, Plus의 자세한 제한, 반복 전송 예시, 산식은 접어서 볼 수 있다.
- 입력과 출력 한도는 만 단위 숫자와 상태 문장으로 요약했다. 200쪽 → 20쪽씩 10회 → 확인·합치기 도식을 추가했다. 다음으로 로컬 처리와 필요한 문단·이미지 재사용의 의미를 설명한다.
- 산식 변경 없음. Node 24 생산 빌드·TypeScript·기존 산식/CSV 테스트 통과. 실제 Chromium에서 $100→6권/3권, 빈 예산 오류, 500토큰 본문 변경, 원본 입력 한도 전환을 확인했다. 320/390/768/1440px 넘침 없음, axe 자동 검사 위반 0. 데스크톱·모바일 결과와 분할 흐름을 스크린샷으로 확인했다.
- 최신 로컬 미리보기: http://127.0.0.1:3031/pdf-to-md#local-cost. 외부 배포와 실제 OCR 품질 실험은 하지 않았다.
